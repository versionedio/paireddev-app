The design in five points

  1. Tables never take direct writes for governed data. Items, checklists, plans, sessions and audit are changed only by Logic Blocks, so gates and “humans only” rules are enforced on the server.
  2. Access is by block-name prefix (pd_req_*, pd_dev_*, pd_own_*, pd_adm_*, pd_agt_*) because platform ACL cannot see request bodies and has a size cap.
  3. Agents are a connector and crews, not a back door. Muse Code runs on a GitHub runner; crews plan, review and pre-flight but only return results. Blocks write them.
  4. GitHub drives card status. Webhooks land in an append-only table, then one block applies each event idempotently.
  5. History is recorded from day one (transitions and nightly snapshots) because the analytics cannot be rebuilt later.

Biggest things to know

  • Live Session fidelity. The runner connector gives phases, not a step-by-step stream or inline hook approval. I recommend a hybrid; see G-01.
  • Backlog scale. Exact totals and page numbers work to about 2,000 rows per tenant; see G-06.
  • Plan tier is unknown. get_usage fails over MCP, and schedules, flags and Glyph volume depend on the plan; see G-02.
  • Console-only steps remain: creating tenants, AI keys, connector secrets, webhook secrets.
