2 · AI providers

The org catalogue already lists 15 providers including anthropic and gemini; no org-level action is needed to use them. Each tenant enables a provider, pastes its own key and picks a default model in Tenant Settings → AI. No MCP call can set a key.

ProviderUsed byRequirementStatus
anthropicPlanner, reviewer, pre-flight crews; default for triage. The coding runner uses whichever provider the tenant picks on the coding-agent connector.7 · Anthropic executionIn catalogue. Tenant key needed.
geminiTriage, scoring, summaries (retro). Not used for write sessions7 · Google, not certified for protected pathsIn catalogue. Tenant key needed.

openai—13 says OpenAI “cannot be brokered”The catalogue does include OpenAI (text, image, speech) and a codex coding-agent connector exists. The requirement text is out of date.

Model choice order: the model named in the call → the connection's saved setting → the workspace default. A model is never silently swapped. A crew agent can name a provider; a missing one fails with provider_not_configured. The project's exec_provider field is passed as provider on crew agents and ai_call steps.

3 · Access

What ACL can and cannot do here. It sees the route name and nothing in the body, and a user's whole policy is capped near 8 KB. So the design is: no direct write access to governed tables for anyone, role access expressed as prefix grants on Logic Block names, and sensitive rules repeated inside the block. userrole is only a label in the token; it grants nothing.
PolicyAllowNotes
pd-requesterblocks pd_req_*; evaluate flags; read own memberDefault for new users via set_default_member_access. Least privilege: a stranger who signs up can submit and vote, nothing else.
pd-devrequester + pd_dev_*; list*/get*/count* on non-sensitive entities; create/update on notification_prefCan own cards, run agents, sign off review items.
pd-ownerdev + pd_own_*; CRUD on project_group, project_group_memberPrioritise, advance, promote, sprints, deliveries, invites.
pd-adminowner + pd_adm_*Permission matrix, tenant-admin hooks, bootstrap.
pd-agentpd_agt_* + pd_dev_get_*, pd_dev_list_*Never signoff, advance, merge, promote, set_owner. Assigned to the agent's service identity only.

The platform's built-in adminacl is * on *. A tenant admin who holds it can write governed tables directly. That is an accepted trust boundary for admins but must not be given to an agent identity. See G-16.

Agents appear in the roster as a member with kind = agent and an operator_member_id. Actions the agent takes through the GitHub runner reach the board via webhooks and pd_sys_* blocks, so the agent does not need a board token for the normal path. A token for Muse Code to drive the board directly (requirement: MCP parity) is covered in G-18.
